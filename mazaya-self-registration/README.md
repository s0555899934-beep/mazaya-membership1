# منصة مزايا العضوية — وحدة التسجيل الذاتي

نموذج أولي برمجي قابل للربط بقاعدة بيانات Supabase، وفق القرارات المعتمدة:
- التسجيل متاح لجمعيات منطقة الرياض فقط.
- حساب الدخول ينشأ فوراً بعد التسجيل (بحسب إعداد تأكيد البريد في Supabase).
- مستخدم واحد لكل جمعية، مع منع تكرار رقم التسجيل.
- فئة العضوية لا تختارها الجمعية؛ يحددها المجلس.
- تفعيل حساب الدخول لا يعني اعتماد العضوية أو إتاحة المزايا. تظل العضوية `pending` حتى اعتماد المجلس.

## المتطلبات
- Node.js 20 أو أحدث
- حساب Supabase
- حساب استضافة مثل Vercel

## التشغيل محلياً
1. فك ضغط المشروع وافتح مجلده في محرر مثل VS Code.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env.local`.
4. ضع رابط مشروع Supabase ومفتاح `anon/public` في `.env.local`.
5. من Supabase افتح SQL Editor ونفّذ محتوى `supabase/schema.sql`.
6. في Supabase Auth > Providers > Email، عطّل Confirm email إذا كان المطلوب تفعيل الدخول فوراً دون انتظار رسالة تأكيد. يفضّل في بيئة الإنتاج تفعيل التحقق من البريد والجوال أو استخدام آلية تحقق مناسبة قبل السماح بالعمليات الحساسة.
7. شغّل `npm run dev` ثم افتح `http://localhost:3000`.

## إنشاء مسؤول المجلس
1. أنشئ حساباً لمسؤول المجلس من صفحة التسجيل أو من Supabase Authentication.
2. من Supabase Authentication > Users انسخ UUID الخاص به.
3. نفّذ في SQL Editor:
   `insert into public.council_admins(user_id) values ('UUID-HERE');`
4. افتح `/admin` بعد تسجيل الدخول بهذا الحساب.

## النشر على Vercel
1. ارفع مجلد المشروع إلى مستودع GitHub خاص بالجهة.
2. أنشئ مشروعاً جديداً في Vercel واربط المستودع.
3. أضف متغيري البيئة `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` من إعدادات Supabase.
4. انشر المشروع، ثم اربط النطاق الرسمي من إعدادات Domains في Vercel.
5. أضف النطاق إلى Supabase Authentication > URL Configuration ضمن Site URL وRedirect URLs.

## تنبيهات قبل الإطلاق الرسمي
هذه نسخة تأسيسية وليست جاهزة للإطلاق العام دون مراجعة تقنية وأمنية. صفحة إدارة المجلس هنا نقطة بداية، ويجب قبل الإنتاج إضافة سجل تدقيق غير قابل للتلاعب، تحقق من رقم الترخيص من مصدر رسمي إن أمكن، CAPTCHA/حدود لمحاولات التسجيل، سياسات خصوصية وموافقة، تحقق بريد/جوال، نسخ احتياطي، ومراجعة سياسات RLS واختبارات اختراق. لا تضع مفتاح `service_role` في المتصفح أو في متغيرات `NEXT_PUBLIC_`.
